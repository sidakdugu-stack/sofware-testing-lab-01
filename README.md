## Ответы на вопросы (задание 6)

### Можно ли начинать реализацию по исходным требованиям без уточнений?
Нет. Не определены «надёжный пароль», «корректный email», правила проверки
возраста и тексты сообщений. Без уточнений разработчик будет угадывать,
что приведёт к переделкам.

### Три риска, требующие первоочередного тестирования
1. Утечка данных пользователя в сообщении об ошибке.
2. Регистрация несовершеннолетнего из-за неверной проверки возраста.
3. Создание дубликатов учётных записей при двойной отправке формы.

### Какие проверки автоматизировать в первую очередь
- Валидацию имени, email и пароля (модульные тесты).
- Проверку уникальности email и границы возраста (интеграционные).
- Защиту от дубликатов при повторной отправке.

### Какие проверки требуют участия человека
- Понятность сообщений об успехе и об ошибках.
- Отображение скрытых символов в поле пароля.
- Общее впечатление от сценария регистрации (UX).

### Какие сведения нужны для определения готовности к выпуску
- Согласованные критерии приёмки по всем шести требованиям.
- Результаты регрессионного прогона, отсутствие критичных дефектов.
- Отчёты о нагрузочном и security-тестировании.
